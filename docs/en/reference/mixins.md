# Mixins

::: tip
This is reference documentation. To learn how to compose these mixins onto your own models, see the [how-to guides](/en/how-to/).
:::

All mixins are composed onto table models via MRO. **MRO order usually matters** — see the "MRO" note under each mixin.

::: info Import locations
Symbols new in 0.5.0 (`GroupSumRow`, the keyset cursor exceptions, `ResourceReferencedError`, the new decorators, `ResourceQuotaMixin`, etc.) are annotated below with the import path of the submodule where they are defined (`sqlmodel_ext.mixins` / `sqlmodel_ext.session` / `sqlmodel_ext.pagination`); these paths always work.
:::

## `TableBaseMixin` / `UUIDTableBaseMixin`

```python
from sqlmodel_ext import TableBaseMixin, UUIDTableBaseMixin
```

The base mixin for async CRUD; for method signatures see [CRUD methods](./crud-methods).

| Field | `TableBaseMixin` | `UUIDTableBaseMixin` |
|------|------|------|
| `id` | `int \| None`, auto-increment primary key | `uuid.UUID`, **UUIDv7** primary key (`default_factory=uuid7`) |
| `created_at` | `datetime`, timezone-aware, written on creation | Same |
| `updated_at` | `datetime`, timezone-aware, explicitly refreshed on every `save()` with changes / non-empty `update()` | Same |

**Class variables**:

| Name | Default | Description |
|------|--------|------|
| `__optimistic_retry_default__` | `0` | Retry count used by `save()` / `update()` when `optimistic_retry_count=None`. `OptimisticLockMixin` overrides it to `3`. `delete()` never retries |

### UUIDv7 primary keys

The first 48 bits of a UUIDv7 (RFC 9562) are a Unix millisecond timestamp, so byte order is creation-time order: `ORDER BY id` approximates creation order, and B-tree inserts concentrate at the right edge (far fewer page splits than UUIDv4). Generated by `sqlmodel_ext.mixins.uuid7` (on Python 3.14+ it uses the standard library `uuid.uuid7` directly; earlier versions use a built-in RFC 9562 implementation, strictly increasing within one process).

Known limitations:

- The id exposes the creation time (millisecond precision). An id is an **identifier, not a credential** — don't rely on it being unguessable.
- Don't treat id order as authoritative time order: the timestamp comes from the application clock and has no global monotonicity across processes.
- Existing rows keep their original UUID version; with mixed v4/v7, byte order is still a consistent total order (usable for lock ordering).
- When you need a **deterministically derived** primary key (e.g. a `uuid5` computed from an idempotency key), assign it explicitly — the default factory only applies when no id is provided.

## `CachedTableBaseMixin`

```python
from sqlmodel_ext import CachedTableBaseMixin
```

Inherits from `TableBaseMixin`. Adds a Redis cache layer to the model's `get()` queries, with automatic invalidation on the write path, and is **transparent to transactions** (see [Cache transparency inside transactions](/en/explanation/transactional-cache-transparency)).

**MRO**: `CachedTableBaseMixin` must come **before** `UUIDTableBaseMixin` / `TableBaseMixin`:

```python
from sqlmodel_ext.mixins import CACHE_TTL_WARM

class Character(CachedTableBaseMixin, CharacterBase, UUIDTableBaseMixin, table=True, cache_ttl=CACHE_TTL_WARM):
    pass
```

**Session requirement**: the session must be the enhanced `sqlmodel_ext.AsyncSession` (`SessionFactory(engine, class_=AsyncSession)` or `async_sessionmaker(engine, class_=AsyncSession)`). Invalidation is orchestrated centrally by its `commit()`.

**Class variables**:

| Name | Type | Default | Description |
|------|------|--------|------|
| `__cache_ttl__` | `int` | `3600` | Cache TTL (seconds). Set with the class keyword `cache_ttl=N` (the metaclass validates it is a positive integer) |
| `on_cache_hit` | `Callable[[str], None] \| None` | `None` | Cache-hit callback; the argument is the model name |
| `on_cache_miss` | `Callable[[str], None] \| None` | `None` | Cache-miss callback (only fires when Redis was actually queried) |

**TTL semantic constants** (`from sqlmodel_ext.mixins import ...`):

| Constant | Value | Use |
|------|------|------|
| `CACHE_TTL_HOT` | `600` | Frequently changing models |
| `CACHE_TTL_WARM` | `1800` | Occasionally changing models |
| `CACHE_TTL_COLD` | `3600` | Rarely changing models (the default) |

**Class methods**:

| Method | Description |
|------|------|
| `configure_redis(client)` | Call once at startup. `client` is a `redis.asyncio.Redis` (`decode_responses=False`). Also installs the session event hooks (idempotent) |
| `check_cache_config()` | Call once at startup (after `configure_redis()`). Validates: Redis is configured; no subclass overrides `_get_client`; `__cache_ttl__` is a positive integer; no subclass method directly calls `invalidate_by_id` / `invalidate_all` etc. (AST check). Also prebuilds the "table name → cached class" index |
| `invalidate_on_commit(session, *ids)` | **Registers** row-level invalidation, executed after that session's next commit. For scenarios where triggers / raw SQL are coupled with an ORM transaction; `ids` only accepts real primary keys (`int` / `UUID`); rollback / `reset()` discards the registration, so retry paths must call it again |
| `async invalidate_by_id(*ids)` | **Immediately** invalidates the given IDs (for external callers: admin scripts, tests). Redis errors are logged and swallowed |
| `async invalidate_all(*, strict=False)` | Immediately invalidates all of this model's cache (`id:` + `query:`). `strict=False` swallows Redis errors; `strict=True` logs and re-raises so the caller can tell success from failure |
| `register_raw_dml_write(session, statement)` | Write-side observation point for raw DML: registers the written tables as "written but uncommitted", and warns on an `UPDATE` / `DELETE` that hits a cached table without any registered invalidation. The enhanced session's `execute` / `exec` / `scalar` / `stream` / `stream_scalars` already call it automatically |

::: warning Don't call `invalidate_by_id` / `invalidate_all` directly inside model methods
`check_cache_config()` rejects this pattern (accessing expired attributes after commit triggers MissingGreenlet). Inside model methods, register with `invalidate_on_commit(session, ...)`, then `await session.commit()`.
:::

**Extra `get()` parameter**: `no_cache: bool = False`. Only the `get()` of cached models has this parameter; passing it to a non-cached model raises `TypeError`. `get_one()` / `get_exist_one()` have no `no_cache`; to bypass the cache use `authoritative=True` or `with_for_update=True`.

**Conditions that skip the cache (both read and write)**: `no_cache=True`, `authoritative=True`, `with_for_update=True`, `populate_existing=True`, non-empty `options`, non-empty `join`, and **uncommitted writes in this transaction to any table the query depends on**.

## `OptimisticLockMixin`

```python
from sqlmodel_ext import OptimisticLockMixin, OptimisticLockError
```

**MRO**: `OptimisticLockMixin` must come **before** `UUIDTableBaseMixin` / `TableBaseMixin` (so that its override of `__optimistic_retry_default__` takes effect).

**Fields**:

| Field | Type | Database | Description |
|------|------|--------|------|
| `oplock_version` | `int` (`0 ≤ v ≤ JS_MAX_SAFE_INTEGER`) | `BIGINT`, `server_default 0` | SQLAlchemy `version_id_col`, auto-incremented on every UPDATE. **`exclude=True`**: does not appear in `model_dump()` |

The column is named `oplock_version` rather than `version` to avoid clashing with a domain field `version`. `server_default` keeps INSERTs from old instances that don't know the column valid during a rolling deployment.

**Class variables**:

| Name | Value | Description |
|------|------|------|
| `__optimistic_retry_default__` | `3` | Overrides the base's `0`: conflicts are retried internally 3 times by default before `OptimisticLockError` is raised |
| `_has_optimistic_lock` | `True` | The metaclass uses it to wire `version_id_col` on the root table's mapper (STI/JTI subclasses share it via mapper inheritance). It can be overridden to `False` on an **intermediate base class**: keeps the version column without enabling locking behavior (step one of a two-phase rollout). The metaclass checks the flag on the **base classes**, so writing it in the `table=True` class's own body has no effect |

The name `oplock_version` is globally reserved: any model declaring it in its own class body raises `TypeError` at class creation (use `version` / `revision` etc. for domain version fields).

```python
from typing import ClassVar

class ColumnOnlyOptimisticLock(OptimisticLockMixin):
    _has_optimistic_lock: ClassVar[bool] = False   # Phase one: ship the column only

class Order(ColumnOnlyOptimisticLock, OrderBase, UUIDTableBaseMixin, table=True):
    pass   # has the oplock_version column, but version_id_col is not wired
```

**Trigger condition**: the `WHERE oplock_version = ?` of an UPDATE / DELETE doesn't match (0 rows affected) → `StaleDataError` → converted to `OptimisticLockError` by `save()` / `update()` / `delete()`.

## `OptimisticLockError`

```python
class OptimisticLockError(Exception):
    model_class: str | None
    record_id: str | None
    expected_version: int | None
    original_error: StaleDataError | None
```

| Source | `model_class` | `record_id` | `expected_version` |
|------|------|------|------|
| `save()` / `update()` retries exhausted | Model name | Record id | Version on the instance at conflict time |
| `save()` / `update()` record deleted during retry | Model name | Record id | `None` |
| `delete()` | **Caller's** model name | Always `None` | Always `None` |

## `register_sti_columns_for_all_subclasses()`

```python
from sqlmodel_ext import (
    register_sti_columns_for_all_subclasses,
    register_sti_column_properties_for_all_subclasses,
)
```

```python
def register_sti_columns_for_all_subclasses() -> None
def register_sti_column_properties_for_all_subclasses() -> None
```

STI subclass fields must be registered to the parent table in two phases:

1. `register_sti_columns_for_all_subclasses()` — call **before** `configure_mappers()`
2. `register_sti_column_properties_for_all_subclasses()` — call **after** `configure_mappers()`

::: warning STI shared columns must be nullable in the database
Subclass columns registered to the parent table have their `default` / `server_default` stripped, so every INSERT from a sibling subclass writes an **explicit NULL** into that column (an explicit NULL bypasses the database DEFAULT). Migration authors must ensure: **such columns never get NOT NULL, and never rely on a database DEFAULT to fill values for sibling subclasses**. If you only want to require non-null for the subclass that owns the column, use a NULL-tolerant CHECK: `discriminator <> 'owner_identity' OR col IS NOT NULL`. In a test database built by `create_all` the column is nullable anyway, so violations only fail on a migrated database.
:::

## `DeferredIndex`

```python
from sqlmodel_ext import DeferredIndex
```

```python
class DeferredIndex(CustomTableArg):
    def __init__(self, name: str, *column_names: str, **kwargs: Any) -> None
```

A **deferred index marker** for an STI base class's `table_args`. STI subclass columns are registered dynamically in phase 1 and don't yet exist when the base class's `__table_args__` is evaluated — writing `Index('name', 'col')` directly raises `ConstraintColumnNotFoundError` immediately. `DeferredIndex` is intercepted by the metaclass (not passed to SQLAlchemy) and materialized as a real `Index` at the end of `register_sti_columns_for_all_subclasses()`.

```python
class CanvasNode(
    SQLModelBase, UUIDTableBaseMixin, PolymorphicBaseMixin,
    table=True,
    table_args=(
        DeferredIndex('ix_canvasnode_file_ids_gin', 'file_ids', postgresql_using='gin'),
    ),
):
    ...
```

- `name` — index name (unique across the database)
- `*column_names` — column name strings (columns that STI subclasses register to the parent table)
- `**kwargs` — passed through to SQLAlchemy `Index` (e.g. `unique=True`, `postgresql_using='gin'`)

## `RelationPreloadMixin`

```python
from sqlmodel_ext import RelationPreloadMixin
```

Classes inheriting this mixin can decorate methods with `@requires_relations` (for the transaction-contract decorators see [Decorators & helpers](./decorators)).

**`__init_subclass__` behavior**: for SQLModel classes, scans every method carrying `_required_relations` metadata and performs import-time validation (spell-checking string relationship names). Declarations on pure-Python mixins are validated when they are mixed into a concrete SQLModel class.

**Methods**:

| Method | Description |
|------|------|
| `async ensure_relations_loaded(session, relations)` | **Public entry point**: ensures the given relationships are loaded, incrementally loading only the missing ones (one query). `@requires_relations` calls it automatically; if the decorated method's signature has no session (the decorator skips preloading when it can't find a session), orchestration code must call it first itself |
| `async ensure_relations_loaded_bulk(session, instances, specs_by_class)` (classmethod) | Bulk-preloads relationships for a batch of (possibly heterogeneous) instances. Query count = 0–1 owner refresh + 1 per target inheritance-tree root. Only batches many-to-one relationships "with a single-column foreign key to the target's `id` and a `primaryjoin` that is a plain foreign-key equality"; when the foreign key is non-null but the target row is missing, it **deliberately does not assemble** (left unloaded, so `raise_on_sql` access fails loudly). This is a query-count optimization, not a source of correctness — you should still call `ensure_relations_loaded` on each instance afterwards (a no-op when already loaded) |
| `bulk_preload_unsupported_reason(spec)` (classmethod) | Single source of truth for the bulk capability boundary: returns `None` when supported, otherwise a human-readable reason. Startup checks can use it to fail loudly on declarations that can't be batched |
| `get_relations_for_method(method_name)` (classmethod) | Relationships declared by a method, as `list[QueryableAttribute]` |
| `get_relations_for_methods(*method_names)` (classmethod) | Relationships declared by several methods (deduplicated by key) |
| `async preload_for(session, *method_names)` | Manually preloads for the given methods; returns `self` for chaining |

## `ResourceQuotaMixin`

```python
from sqlmodel_ext.mixins import (
    ResourceQuotaMixin,
    QuotaExceededError,
    QuotaOwnerNotFoundError,
    CallerDidNotCommitError,
)
```

Atomic quota-slot acquisition for "each owner may have at most N resources". Depends on no application concepts, only on `AsyncSession`; the host class must also inherit a table base class that provides `count()` (unless it overrides `_count_owner_resources`).

**Subclass contract** (three classmethods must be implemented):

| Method | Description |
|------|------|
| `async _lock_owner(session, owner_id, *, with_for_update=True)` | Loads and returns the owner row (`SELECT ... FOR UPDATE` when `with_for_update`), or `None` if it doesn't exist; must forward `with_for_update` to the underlying `get` |
| `_quota_condition(owner_id) -> ColumnElement[bool]` | Selects this owner's rows in this model |
| `_quota_max(owner) -> int` | Maximum count allowed for this owner |
| `async _count_owner_resources(session, owner_id, owner) -> int` | Optional override; defaults to `cls.count(session, _quota_condition(owner_id))` |

**Entry points**:

| Method | Description |
|------|------|
| `async preflight_quota(session, owner_id, count=1)` | **Lock-free** preflight (a cheap, best-effort, racy soft gate), placed before expensive steps (e.g. a paid external API) |
| `acquire_quota_lock(session, owner_id, count=1, defer_commit=False, idempotent_check=None)` | `async with` context: locks the owner row within the caller's transaction, checks `current + count <= max`, and runs atomically with the protected INSERT. The block itself doesn't commit — the caller must commit (the lock is released on commit/rollback) |

| Parameter | Description |
|------|------|
| `count` | Number of slots to reserve (`>= 1`) |
| `defer_commit` | When `True`, disables the "block exited normally without a commit" guard — for cases where `save(commit=False)` is followed by commit in a larger outer transaction |
| `idempotent_check` | Optional callback run after the lock is acquired and before counting; if it returns non-`None`, the quota check and INSERT are skipped and that value is `yield`ed to the caller (a race guard for concurrent get-or-create). The callback must read database truth (bypassing the cache) |

**Exceptions**:

| Exception | Base class | `status_code` | Condition |
|------|------|------|------|
| `QuotaExceededError` | `ValueError` | `400` | `current + count > max_allowed`; carries `model_name` / `max_allowed` / `current_count` |
| `QuotaOwnerNotFoundError` | `LookupError` | `404` | `_lock_owner` returned `None`; carries `owner_id` |
| `CallerDidNotCommitError` | `RuntimeError` | — | `defer_commit=False` and the block exited normally without a commit (programming error) |
| `ValueError` | — | — | `count < 1` |

For usage see [More mixins: quotas, fuzzy search, cross-table scans, migration cache invalidation](/en/how-to/extra-mixins#resourcequotamixin).

## `TrgmSearchableMixin`

```python
from sqlmodel_ext.mixins import TrgmSearchableMixin, TrgmSearchRequest, BIGRAM_FUNCTION_SQL
```

Fuzzy search over name / text columns based on PostgreSQL `pg_trgm` (**PostgreSQL only**). Only produces a `WHERE` condition; never changes ordering.

| Class variable | Default | Description |
|------|------|------|
| `__trgm_name_column__` | `'name'` | Primary name column: `ILIKE` substring match **OR** the `%` similarity operator (can use a GIN index) |
| `__trgm_text_columns__` | `()` | Other text columns: `ILIKE` substring match only |

| Symbol | Description |
|------|------|
| `trgm_search_condition(query)` (classmethod) | Builds the fuzzy-search condition; `query` must already be stripped and non-empty |
| `TrgmSearchRequest` | Query-parameter DTO: `query: Str64 \| None = None`; `normalized_query` property (`None` if empty after stripping); `apply_condition(model, condition=None)` ANDs the fuzzy condition into an existing condition, returning `condition` unchanged when there is no effective search term |
| `BIGRAM_FUNCTION_SQL` | DDL for `public.bigrams(text) -> text[]`, to be executed once in a migration. Once any index depends on it, **do not change the function body** |

Host contract: the database has run `CREATE EXTENSION pg_trgm` and created `public.bigrams`; GIN indexes exist on the searched columns (otherwise it degrades to a sequential scan); searched columns use the database default collation.

## `MixinTableScanMixin`

```python
from sqlmodel_ext.mixins import MixinTableScanMixin
```

Provides cross-table discovery + parameterized scanning for "the same field-level mixin mounted on several unrelated physical tables". Has no data fields and doesn't participate in CRUD.

| Method | Description |
|------|------|
| `_concrete_mixin_subclasses()` (classmethod) | Recursively discovers every **concrete table class** that mounts this mixin, deduplicated by `__table__` (only the polymorphic root is kept for an STI family) |
| `async _scan_rows_where(session, condition_factory)` (classmethod, async generator) | Runs the condition built by `condition_factory(table_cls)` on each table, `yield`ing `(table_class, row)`. Conditions are built with type-safe expressions; **string field names are not accepted** |

## Migration-driven cache invalidation

```python
from sqlmodel_ext.mixins import (
    run_pending_migration_cache_invalidations,
    collect_migration_invalidation_tasks,
)
```

```python
async def run_pending_migration_cache_invalidations(
    base_class: type,
    *,
    tasks: dict[str, list[str]] | None = None,
    alembic_ini: str = 'alembic.ini',
) -> None

def collect_migration_invalidation_tasks(alembic_ini: str = 'alembic.ini') -> dict[str, list[str]]
```

Call once at startup (after migrations complete and after `configure_redis()`). Each task is `sentinel -> [model class name, ...]`: when the sentinel `cache_invalidation:<sentinel>` doesn't exist in Redis, `invalidate_all(strict=True)` is run for each model, and the sentinel is written only if all succeed (failed tasks are retried on the next startup). With `tasks=None`, tasks are collected from the module-level `CACHE_INVALIDATIONS` constants in Alembic migration files (requires the optional dependency `alembic`; when it isn't installed, `collect_migration_invalidation_tasks` raises `RuntimeError`). For usage see [More mixins: quotas, fuzzy search, cross-table scans, migration cache invalidation](/en/how-to/extra-mixins#migration-driven-cache-invalidation).

## Exceptions overview (`sqlmodel_ext.mixins`)

| Exception | Base class | `status_code` | Raised by |
|------|------|------|------|
| `ResourceReferencedError` | `Exception` | `409` | `delete()`: row still referenced by a foreign key. Attributes `friendly_message` / `constraint_name` / `original_error` |
| `KeysetCursorError` | `ValueError` | `422` | Common base class for keyset cursor misuse; `str(e)` is safe to return to the client |
| `KeysetCursorInvalidError` | `KeysetCursorError` | `422` | The `after_id` anchor doesn't exist or isn't visible |
| `KeysetCursorUnsupportedError` | `KeysetCursorError` | `422` | The query has its own `order_by` or uses `join` |
| `OptimisticLockError` | `Exception` | — | See above |

`FK_DELETE_RESTRICT_FALLBACK_MESSAGE`: the generic message `ResourceReferencedError` uses when no message is registered for the foreign-key constraint (contains no table / column / constraint names).

## Default `lazy='raise_on_sql'`

The default `lazy` of every SQLModel `Relationship` field is `'raise_on_sql'`: accessing a relationship that wasn't preloaded **raises immediately** instead of triggering an implicit synchronous query. This is the last safety net against the MissingGreenlet problem.
