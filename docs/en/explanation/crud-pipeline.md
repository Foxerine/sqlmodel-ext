# CRUD pipeline

::: tip Source location
`src/sqlmodel_ext/mixins/table.py` — `TableBaseMixin` and `UUIDTableBaseMixin`
:::

This chapter explains how `save()` / `get()` / `update()` / `delete()` and friends work internally. For full signatures see [CRUD methods reference](/en/reference/crud-methods); for typical usage see the [How-to guides](/en/how-to/).

## `TableBaseMixin` basics

```python
class TableBaseMixin(AsyncAttrs):
    _has_table_mixin: ClassVar[bool] = True          # Lets the metaclass identify "this is a table class"
    __optimistic_retry_default__: ClassVar[int] = 0  # Optimistic lock retry policy (OptimisticLockMixin overrides it to 3)

    id: int | None = Field(default=None, primary_key=True)
    created_at: datetime = Field(default_factory=now, sa_type=DateTime(timezone=True))
    updated_at: datetime = Field(
        sa_type=DateTime(timezone=True),
        sa_column_kwargs={'default': now, 'onupdate': now},
        default_factory=now,
    )

class UUIDTableBaseMixin(TableBaseMixin):
    id: uuid.UUID = Field(default_factory=uuid7, primary_key=True)
```

- Inheriting `AsyncAttrs` enables `await obj.awaitable_attrs.some_relation` on model objects.
- `_has_table_mixin = True` lets the metaclass automatically add `table=True` in `__new__`.
- Timestamps are all **timezone-aware** UTC.
- UUID primary keys use **UUIDv7**: the first 48 bits are a millisecond timestamp, so byte order is creation order, B-tree inserts concentrate on the right edge, and page splits are far rarer than with UUIDv4. Python 3.14+ uses the standard library `uuid.uuid7` directly; earlier versions use a built-in RFC 9562 implementation (strictly increasing within a process). The JTI child-table primary key generated by `create_subclass_id_mixin()` uses the same factory — if the two differed, JTI subclasses would silently get a different UUID version.

## `save()` implementation

```python
async def save(self, session, load=None, refresh=True, commit=True,
               jti_subclasses=None, optimistic_retry_count=None):
    retries_remaining = (optimistic_retry_count if optimistic_retry_count is not None
                         else cls.__optimistic_retry_default__)
    while True:
        # Snapshot id / oplock_version before flush (after a conflict rollback every attribute is expired, and reading it again would emit SQL)
        # When a retry is needed, record "the columns I actually changed" from attribute history
        session.add(instance)
        if <persistent instance with column changes>:
            instance.updated_at = now()      # explicit assignment, see below
        try:
            await (session.commit() if commit else session.flush())
            break
        except StaleDataError:
            ...                              # optimistic lock retry, see "Optimistic lock mechanism"

    if not refresh:
        return instance
    _insp = inspect(instance)                # after commit, read id safely from the identity
    return await cls.get(session, cls.id == _insp.identity[0], load=load, jti_subclasses=jti_subclasses)
```

### Why `updated_at` is assigned explicitly

A column-level `onupdate` fires only when **that table** is UPDATEd. Under JTI, if only child-table columns changed, the parent table (where `updated_at` lives) is never UPDATEd, `onupdate` never fires, and the timestamp stays at its old value. So whenever a persistent instance has column changes (`session.is_modified(instance, include_collections=False)` — pure collection changes don't UPDATE this row and don't count), `save()` writes `updated_at` explicitly; `update()` does the same for any non-empty update. INSERT timestamps come from the field defaults.

### Why you must use the return value

::: danger Object expiration
`session.commit()` expires **all objects in the Session**. Accessing attributes of the original object again triggers an implicit query — which in async code means `MissingGreenlet`. `save()` returns a fresh object re-read via `cls.get()` (cached models read bypassing the cache and refill it).
:::

## `update()` implementation

```python
async def update(self, session, other, extra_data=None, exclude_unset=True, exclude=None, ...):
    update_data = other.model_dump(exclude_unset=exclude_unset, exclude=exclude)
    instance.sqlmodel_update(update_data, update=extra_data)
    if update_data or extra_data:
        instance.updated_at = now()
    session.add(instance)
    await session.commit()
```

::: tip PATCH semantics come from the type, not a switch
Fields of a DTO derived with `partial=True` default to `Unset`, and `Unset` fields never appear in `model_dump()` — a field "the client didn't send" does not exist at the data level, so it is naturally never written; a `null` the client sent explicitly is a real value and is written as NULL. `exclude_unset=True` is still the default, but PATCH correctness no longer depends on it.
:::

## `delete()` implementation

```python
@classmethod
async def delete(cls, session, instances=None, *, condition=None, commit=True) -> int:
    try:
        if condition is not None:
            stmt = sql_delete(cls).where(condition)
            if (sti := cls._sti_descendants_condition()) is not None:
                stmt = stmt.where(sti)            # don't delete rows of STI sibling subclasses
            deleted = (await session.execute(stmt)).rowcount
        else:
            for inst in instances_list:
                await session.delete(inst)
        if commit:
            await session.commit()
    except IntegrityError as e:
        if sqlstate == '23503' and e.statement.lstrip().upper().startswith('DELETE'):
            raise ResourceReferencedError(<registered message or fallback message>, constraint, e) from e
        raise
    except StaleDataError as e:
        raise OptimisticLockError(..., record_id=None, expected_version=None) from e
```

Two things worth noting:

- **The direction of a foreign-key violation can only be decided by the call site.** "Inserting a child row whose parent doesn't exist" and "deleting a parent row that is still referenced" are the same exception at the driver level; moreover commit flushes every pending operation in the session, so a bad INSERT queued earlier may also surface here. The translation therefore requires two conditions at once: it is caught inside `delete()`, **and** the failing statement is a `DELETE` (`IntegrityError.statement` is generated by SQLAlchemy and independent of the server language).
- **Two `@overload`s** make "passing neither `instances` nor `condition`" fail at type-check time with "no matching overload", promoting a runtime invariant to a compile-time constraint.

## `get()` implementation

For the full signature see [reference/crud-methods](/en/reference/crud-methods#get). Processing order:

### 1. `table_view` merge + sort tie-breaker column + keyset cursor

```python
if isinstance(table_view, TimeFilterRequest):   # time filters: explicit arguments take precedence
    ...
if isinstance(table_view, PageWindowRequest):   # offset / limit: explicit arguments take precedence
    ...
if isinstance(table_view, PaginationRequest):
    if table_view.after_id is not None and (order_by is not None or join is not None):
        raise KeysetCursorUnsupportedError(...)
    if order_by is None:
        order_col = col(getattr(cls, table_view.order or 'created_at'))
        direction = desc if table_view.desc else asc
        order_by = [direction(order_col)]
        if order_field != 'id':
            order_by.append(direction(col(cls.id)))     # id tie-breaker column
    if table_view.after_id is not None:
        keyset_condition = await cls._build_keyset_condition(session, table_view, condition, filter)
```

**id tie-breaker column**: `created_at` is not unique (rows created in the same batch share a timestamp), rows with equal values have no deterministic order, and both offset and keyset pagination would skip or repeat rows at page boundaries. Appending `id` in the same direction makes the order total.

**The keyset anchor query** uses the same FROM as the main query (`with_polymorphic` for a JTI base class) and the same visibility (`condition` + `filter` + STI filter): the anchor's sort values are looked up on the server, the client only sends the id; an invisible anchor raises the same error as "does not exist", so the difference can't be used to probe rows outside the scope.

### 2. Polymorphism

```python
if is_jti:
    statement = select(with_polymorphic(cls, '*'))   # auto-JOINs all child tables, avoiding N+1
else:
    statement = select(cls)
if (sti := cls._sti_descendants_condition()) is not None:
    statement = statement.where(sti)                 # WHERE _polymorphic_name IN (...)
```

SQLAlchemy/SQLModel do not automatically add a discriminator filter to STI subclass queries (sqlalchemy#5018, sqlmodel#488). `_sti_descendants_condition()` is the single condition **shared** by `get()` / `count()` / `delete(condition=)` / the keyset anchor / the aggregate methods, guaranteeing they all see the same scope.

### 3. Conditions, time filters, JOIN, options

`condition` → keyset condition → time filters (left-closed, right-open) → `join` → `options`.

### 4. Relation preloading

```python
load_chains = cls._build_load_chains(load_list)
for chain in load_chains:
    loader = selectinload(chain[0])
    for rel in chain[1:]:
        loader = loader.selectinload(rel)
    statement = statement.options(loader)
```

`_build_load_chains` detects dependencies automatically: `[rel(User.profile), rel(Profile.avatar)]` → `selectinload(User.profile).selectinload(Profile.avatar)`. A bidirectional relation pair (`A.b` + `B.a`) makes every relation somebody else's successor, so none appears under any root; in that case the cycle is broken at its first member in list order, instead of silently dropping the requested load.

### 5. Ordering, pagination, row locks

```python
if with_for_update:
    statement = statement.with_for_update(of=cls if polymorphic else None, skip_locked=skip_locked)
if with_for_update or populate_existing or authoritative:
    statement = statement.execution_options(populate_existing=True)
```

- Polymorphic models use `FOR UPDATE OF <main table>` (PostgreSQL does not allow locking the nullable side of a LEFT OUTER JOIN).
- **Locking reads force `populate_existing`**: the database returns the latest row, but the identity map by default hands back the already-loaded stale object — the following read-modify-write would be a lost update.
- At this layer `authoritative` is just `populate_existing` (cached models additionally bypass Redis); it is `or`-ed with the caller's `populate_existing` and never weakens it.

### 6. `fetch_mode` determines the return value + lock tracking

```python
result = await session.exec(statement)
if fetch_mode == "one":   instance = result.one()
elif fetch_mode == "first": instance = result.first()
else:                     instances = list(result.all())
# with with_for_update, record id(instance) in session.info[SESSION_FOR_UPDATE_KEY]
```

## FOR UPDATE tracking

With `with_for_update=True` the `id()` of each locked instance is written into `session.info[SESSION_FOR_UPDATE_KEY]`, for runtime checks by `@requires_for_update` / `@requires_locked_param`. The lifecycle of this set is maintained by module-level session event listeners (independent of caching, always active):

| Event | Handling |
|-------|----------|
| outermost commit / rollback | cleared (locks are released with the transaction) |
| savepoint begins | push a snapshot of the current set |
| savepoint rolled back | restore the snapshot (PostgreSQL releases locks acquired inside the savepoint and keeps earlier ones) |
| savepoint released (RELEASE) | only pop the snapshot (locks transfer to the outer transaction and are kept) |
| savepoint ended via `close()` | conservatively restore the snapshot (drop the inner locks — fail-closed, forcing a re-lock) |

The enhanced session's `reset()` / `close()` also clear it.

## `rel()` and `cond()`

```python
def rel(relationship: object) -> QueryableAttribute[Any]:
    if not isinstance(relationship, QueryableAttribute):
        raise AttributeError(...)
    return relationship

def cond(expr: ColumnElement[bool] | bool) -> ColumnElement[bool]:
    return cast(ColumnElement[bool], expr)
```

Similar to SQLModel's `col()`: basedpyright infers `User.profile` as `Profile` and `Model.field == value` as `bool`; these two functions narrow them into types that can be passed to `load=` / combined with `&` `|`.

## `get_one()` / `get_exist_one()`

```python
@classmethod
async def get_one(cls, session, id, *, load=None, with_for_update=False, authoritative=False):
    return await cls.get(session, col(cls.id) == id, fetch_mode='one',
                         load=load, with_for_update=with_for_update, authoritative=authoritative)

@classmethod
async def get_exist_one(cls, session, id, load=None, *, detail="Not found", with_for_update=False):
    instance = await cls.get(session, col(cls.id) == id, load=load, with_for_update=with_for_update)
    if instance is None:
        if _FastAPIHTTPException is not None:   # `from fastapi import HTTPException` at import time, else None
            raise _FastAPIHTTPException(status_code=404, detail=detail)
        raise RecordNotFoundError(detail)
    return instance
```

`UUIDTableBaseMixin` overrides both to accept only `uuid.UUID`. Whether FastAPI is installed is detected **at module import time**, so FastAPI does not become a hard dependency.

## IntegrityError friendly messages

`sanitize_integrity_error()` / `lookup_integrity_violation_message()` dispatch by SQLSTATE:

| SQLSTATE | Handling |
|----------|----------|
| `23505` unique constraint | look up the `register_unique_violation_message` registry |
| `23503` foreign key | look up the `register_foreign_key_violation_message` registry (the "referenced resource does not exist" direction) |
| `23514` with a `constraint_name` | look up the `register_check_violation_message` registry; never return the raw message (the CHECK expression may contain column names) |
| `23514` without a `constraint_name` | trigger `RAISE EXCEPTION`: the message itself was written by the developer for users, so its first line is returned |

The asyncpg adapter forwards only `sqlstate`, not `constraint_name`, so the constraint name falls back to being read from `orig.__cause__` (the real driver exception) — otherwise every registry lookup would miss. Trigger messages are likewise read from `__cause__`, to avoid leaking the driver exception class-name prefix to users.

## `count()` / `distinct_column()` / `group_sum()`

Each is a single database-level aggregate statement, sharing the STI filter:

```python
count_expr = func.count(distinct(distinct_column)) if distinct_column is not None else func.count()
statement = select(count_expr).select_from(cls)

statement = select(distinct(column)).select_from(cls)                # distinct_column

sum_exprs = [func.coalesce(func.sum(c), 0) for c in sum_columns]      # group_sum
statement = select(group_by, func.count(), *sum_exprs).select_from(cls).group_by(group_by)
```

`group_sum()` converts all sums to `Decimal` (PostgreSQL `NUMERIC` already is `Decimal`; SQLite may yield `int` / `float`, converted via `str()` to avoid binary floating-point residue). `GroupSumRow` is a `SQLModelBase` generic: it is only a method return value and never enters OpenAPI, so it is unaffected by SQLModel's generic JSON schema problem (`ListResponse` is affected, which is why it inherits `BaseModel`).

## `get_with_count()` implementation

```python
items = await cls.get(session, condition, fetch_mode="all", table_view=table_view, ...)
total_count = await cls.count(session, condition, time_filter=time_filter)
return ListResponse(count=total_count, items=items)
```

**Fetch data first, count second**: `get()` performs all validation of the keyset cursor (`after_id` against `order_by` / `join`, anchor validity); counting first would waste an aggregate query on a request that is bound to fail. `count` is not affected by `after_id`.
